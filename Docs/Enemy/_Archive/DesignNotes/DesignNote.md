# 敌人设计备注

> 记录设计规范和机制

---

## 敌人行动设计规范

### 行动池机制

敌人设计时，将行动和特性设计为**行动池**和**机制组（列表）**。

正式遭遇时，从行动池中**随机抽取**组成该敌人的行动栏。

### 示例

例如"蚀影咒骸"的行动池：

| 行动池 |
|------|
| 蚀序诅咒 |
| 暗影冲击 |
| 群体诅咒 |
| 毒液攻击 |

正式遭遇时随机抽取3个组成行动栏。

## 设计原则

### 核心原则

敌人设计应专注于**战斗机制**、**状态联动**和**行动协同**，尽量避免影响行动运转流程的设计。

### 行动运转流程

指敌人执行行动的顺序、行动值积累、回合结构等底层机制。这类设计应该尽量简洁。

### 应该关注的

- 行动的效果（伤害、施加状态等）
- 状态之间的联动（叠加、引爆、转化等）
- 行动与特性之间的配合

### 应该避免的

- 复活、跳过回合、强制等待等影响流程的设计
- 复杂的状态生命周期管理
- 需要追踪额外行动槽位的设计

---

## 机制组

敌人的特性/被动以**机制组**形式设计。

正式遭遇时，可能激活1个或多个机制。
